Asymptotic Velocity vs Naive Linear Expansion

Why basic bots inevitably die around scores 3,000–5,000, and how the asymptotic curve enables survival at 50,000+.

Flawed Approach

Naive Linear Look-Ahead

look_ahead = base + growth_factor * elapsed_time
  • ❌ Fatal Early Jumps: Chrome hits a hard velocity ceiling of ~13 px/frame at score ~3,500. Linear formulas keep growing infinitely.
  • ❌ Landing Onto Cacti: Dino jumps 300+ pixels ahead of the obstacle, landing straight onto the spikes before recovery.
  • ❌ Dead Zone Bug: Shifting the box anchor forward creates a blind spot directly in front of the Dino's snout.
Production Architecture (v1.0.0)

True Asymptotic Engine Model

v(t) = v₀ + (v_max - v₀) · [1 - exp(-k · t)]
  • ✅ Plateau Convergence: Look-ahead smoothly clamps at exactly 195 px as speed reaches Chrome's 13 px/frame cap.
  • ✅ Fixed Snout Anchor: Left edge anchored rigidly at Dino nose; only the width expands forward dynamically.
  • ✅ Dynamic Jump Durations: Variable hop duration (25ms short, 50ms medium, 68ms high) based on cluster width.

4-Tier Autonomous Architecture

A zero-ML, ultra-lightweight system designed to run under 0.5 ms latency on standard multi-monitor Windows hardware.

TIER 1

Hardware Framebuffer

Direct Win32 GDI `BitBlt` integration capturing only the exact 700x220 canvas sub-rectangle. Slashes capture time from 16.34 ms down to 0.06 ms.

TIER 2

Adaptive Vision Core

Zero-copy NumPy morphology with dynamic Day/Night luminance inversion and strict Y-zone clamping to ignore drifting clouds and stars.

TIER 3

Hardware Scancodes

Direct `SendInput` scancode injection (0x39 Space, 0x50 Down) with zero thread-contention mutex locks preventing race conditions between jumps and ducks.

TIER 4

Telemetry & Post-Mortem

Black-box replay buffer saving the final 10 pre-collision frames. Automated heuristics classify death causes and auto-tune jump hold parameters.
